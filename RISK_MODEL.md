# Модель Риска (Реестр Угроз)

## Назначение

Этот документ описывает единую модель расчета риска для сопоставления:

- профиля угрозы (`model_threat_web`, `model_threat_tg`, `model_threat_forum`)
- профиля объекта (`model_object`)

Модель рассчитана на **любое соотношение** между угрозой и объектом:

- полное совпадение контролей
- частичное совпадение
- отсутствие прямого совпадения

---

## Входные сигналы

Из профиля угрозы:

- `severity`
- признаки эксплуатации (`active_exploitation`, `exploit_available`)
- последствия (`impact_confidentiality`, `impact_integrity`, `impact_availability`)
- `llm_confidence`
- флаги контролей в `depth` (true/false)
- `signal_terms`
- `targeted_levels`

Из профиля объекта:

- флаги контролей в `depth` (true/false)
- текстовые поля с деталями контролей (ПО/оборудование)
- `businessCriticality` (если задано)

---

## Ключевые компоненты

### 1. Интенсивность угрозы `T`

`T` вычисляется из severity, состояния эксплуатации, confidence и CIA-impact:

- выше severity/эксплуатация/CIA -> выше `T`
- значение ограничено диапазоном `[0,1]`

### 2. Прямая применимость `A`

Формируется целевой профиль из контролей угрозы в `depth` (`true` = целевой контроль).

Для целевых контролей:

- если контроль на объекте **отсутствует/false** -> уязвимость выше
- если контроль на объекте **включен/true** -> риск по этому контролю снижается

`A` зависит от:

- доли уязвимых целевых контролей
- семантического совпадения (`signal_terms` vs поля деталей объекта)

Если у угрозы нет явных целевых контролей, `A` понижается и трактуется как слабая применимость.

### 3. Слабость защиты объекта `W`

Рассчитывается по:

- общей доле включенных контролей на объекте
- доле уязвимых контролей среди целевых

Чем больше недостающих контролей, тем выше слабость.

### 4. Экспозиция `E`

`E = 0.6 * A + 0.4 * W`

### 5. Релевантность `R`

`R` объединяет:

- прямую применимость
- семантическое совпадение терминов
- confidence

### 6. Критичность объекта `C`

`C` отражает бизнес-критичность и слабость защиты:

- чем выше критичность и слабее защита, тем выше `C`

---

## Итоговый балл

`risk_score = clamp(0.45*T + 0.30*E + 0.15*R + 0.10*C)`

`risk_score` находится в диапазоне `[0,1]`.

Процент для интерфейса:

- `risk_percent = risk_score * 100`

---

## Правила для крайних случаев

### Нет прямых совпадений контролей

Если угроза не сопоставляется с контролями объекта и семантическое совпадение слабое:

- итог ограничивается фоновым уровнем (`<= 0.20`)
- интерпретация: "нет прямого совпадения контролей, фоновый риск"

### Полное покрытие целевых контролей

Если целевые контроли есть, но на объекте они все включены:

- итог ограничивается (`<= 0.35`)
- интерпретация: "целевая область закрыта действующими мерами"

---

## Уровни риска

- `high`  : `score >= 0.75`
- `medium`: `0.50 <= score < 0.75`
- `low`   : `0.30 <= score < 0.50`
- `n/a`   : `< 0.30` (фоновый уровень)

---

## Выходные поля для UI

Для каждой пары "угроза-объект":

- `score`
- `level`
- `threatIntensity`
- `exposureScore`
- `relevanceScore`
- `weaknessScore`
- `objectCriticality`
- `reasons[]` (ключевые факторы объяснения)

Это делает расчет риска прозрачным и проверяемым в таблице Реестра Угроз.
